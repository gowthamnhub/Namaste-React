What is React?

	How to make our normal Html file/application a React enabled?

	One by importing CDN links.
	
	<!--CDN React-->
    <script
      crossorigin
      src="https://unpkg.com/react@18/umd/react.development.js"
    ></script>
    <script
      crossorigin
      src="https://unpkg.com/react-dom@18/umd/react-dom.development.js"
    ></script>
	
	react.development.js - Core of the react - core framework react algorithm.
	react-dom.development.js -  React library for DOM operations, for manipulating DOM.
	
	Why did facebook made two files? can't we club these into single file?
	Because react is core which will be used across devices for mobile (react-native) or for some other devices as well, but react-dom is only for browsers, hence no clubbing of these together. So, react-dom is kind of bridge to connect to the Browser DOM.

			--> npm install -D parcel 
			
			but what does this -D mean? 
			
		Basically there are two dependencies we can install into our project. one is dev dependencies, another is normal dependencies.
		dev - for development environment. - but read more about it online.
		normal - even for production environment.
		
		So with the above command, we tell the package manager (npm) we want dev package/dependency of Parcel. And from the npm repository the parcel package will get installed to our project.
		Parcel is like a beast, it gives amazing power to our app.
		
		
	Once we run the above command - npm install -D parcel 
		> it creates a new file called - package-lock.json - this is the file which holds all the actual versions of the packages used in the app. 
		> when we have package-lock.json , and we run npm install or npm ci (clean and install) it does take the packages from package-lock.json file and installs the same exact versions locked, it does not update the package based on ^ carrot or ~ tilde symbol used in package.json file.
		> when we delete the package-lock.json and re run "npm install" command then it takes the package versions allowed as per the package.json file and create new package-lock.json with updated packages.
		> it is helpful when we test app with certain versions and we commit both package.json and package-lock.json file to prod, in prod server we run "npm install" command we do not want it to update the package, we want it to install the packages which are locked and tested in dev environment.

Like since we installed parcel, it will have parcel related files/folders, and it also installs/downloads all its own respective dependency packages as well (like parcel can depend on some packages, and each dependent package can depend on some packages - this is what known as TRANSITIVE DEPENDENCIES) it would download all of those files to node_modules. Hence node_modules is very heavy folder.

		> Since these are auto generated/downloaded from npm when we run npm install - even if this folder is deleted, again we run npm install it will readd those files back, so need to commit this folder to git.

In general - React.createElement returns an JS object, when it is rendered by ReactDOM it is converted to actual HTML elements and rendered in browser.
		React Element is created.
			- const heading = React.createElement("h1",{id: "heading"},"Hello World from React!");	
			
		React DOM object is created by referring to actual DOM's root element. 
			- const root = ReactDOM.createRoot(document.getElementById("root"));
			- this is the bridge between actual React objects and browser DOM.
			
		Actual DOM is replaced with reactDOM by calling - root.render(heading);


	But onething we can notice here is creating elements with core React like below;
		React.createElement("h1",{id: "heading"},"Hello World from React!");	
		
		this is kind of hard to read right, just for creating h1 tag, it is having bit complex kinda code when building large scale applications, it may become very much unreadable for developers, application will still work, but would be hard for developers to read, understand and debug later.
		
		To get rid of this problem, Facebook developers created something called as JSX - which is not HTML inside javascript, but it has HTML or XML like syntax to build react elements.
		
		Eg: 
			const jsxHeading = <h1 id="jsxHeading" style={{color: "blue"}}>Hello World from JSX!</h1>
			
			it looks easier right to read. it is exactly same as above, creating same react object. JSX is the syntax create react elements in HTML like / XML like format.
			
			But this is not a valid JS, JS engine understands only ECMASCRIPT it does not understand JSX. 
			But before even JSX code reaches JS engine, this is transpiled to JS engine understandable code, who does this transpilation - BABEL (but we did not install BABEL right) where does it come from - it is inside PARCEL.
			
			JSX -> PARCEL hands it to BABEL for transpilation -> all jsx elements converted to React.createElement code -> ReactDom then while rendering the elements are converted to HTML elements in browser.
			JSX properties use camelCasing. for class - use className, tabIndex.
			
			BABEL - is not from FACEBOOK, it is a separate package. 
			And Babel also does a lot of code optimization for production builds (like stripping out console.log) and also helps translating modern js ES6+ for older browsers to not break the app in old browsers.
